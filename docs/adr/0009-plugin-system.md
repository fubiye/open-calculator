# ADR-0009：后端插件系统——官方插件 + 配置开关 + 公式函数插件

- 状态：已接受（范围与形态；契约细节/默认开关待确认）
- 日期：2026-11-21
- 关联：[ADR-0007](0007-backend-layering.md) · [后端设计 §7](../architecture/backend.md#7-插件系统) · [技术选型 §7](../architecture/tech-stack.md)

## 背景

后端能力需要可扩展，但插件应当是“可选的、可配置加载的”。Rust 的静态编译决定了三种可选性：构建期裁剪（Cargo feature）、运行期配置、动态加载。项目同时要求 v1 用**公式函数插件**证明扩展点成立，且只做官方插件。

## 决策

### 1. v1 插件范围

- **数据源连接器**：CSV、JSON（官方 crate）；
- **公式函数插件**：至少两类官方插件（建议金融 `FIN_*` + 文本 `TXT_*`），证明不同插件可独立启停；
- AI Provider / 第三方插件后置；
- 所有官方插件默认编入，**不做构建期 feature 裁剪**；仅通过配置文件启用/禁用；
- 不做原生 `cdylib` 动态加载；第三方插件未来走 WASM（wasmtime）沙箱。

### 2. 契约

- `plugin-api` 定义 `PluginManifest`（id/version/kind/apiVersion/capabilities/config schema）与 `Plugin` trait；
- 能力按类型注册（连接器 / 函数），插件不直接注册 HTTP 路由；
- `plugin-host` 负责：发现已编译插件 → 读配置 → schema 校验 → API 版本检查 → 函数名唯一性校验 → 初始化；
- 单个插件失败只禁用该插件，服务降级启动；`/meta` 反映实际启用状态；
- 配置格式：`[plugins.<id>] enabled = true/false` + 插件配置；v1 修改后重启生效。

### 3. 公式函数插件

- 函数实现只有一份：Rust crate；前端不复制业务逻辑；
- 前端拉取 `/functions` 目录后，为每个函数注册 Univer 自定义函数；调用经 `POST /functions/invoke` 到达后端；
- 参数/结果使用统一 tagged Value 编码；插件函数强制命名空间前缀（如 `FIN_`/`TXT_`）；
- 异步桥接依赖 Univer 自定义函数能力，实现前先做最小验证；性能不足时再考虑批量调用或 WASM。

## 理由

- 编译期 + 配置是 Rust 生态中成本最低、最可靠的“可选加载”组合；避免动态库 ABI/安全/跨平台问题；
- 公式函数插件直接证明扩展点，且与“AI 原生/可扩展”方向一致；
- 单份 Rust 实现为未来的 headless/导出计算复用，避免双引擎口径分裂。

## 后果

- 优点：扩展点真实、配置可控、无动态加载风险；插件可独立测试。
- 成本/风险：
  - 所有官方插件都编入二进制，短期体积略增（可接受，后续再加 feature 裁剪）；
  - 公式函数每次调用有一次本地 RPC 开销，需要缓存/测量；
  - Univer 异步自定义函数能力尚未验证，属于 v1 技术风险点。
- 默认开关、命名空间、桥接方式与示例领域见待确认清单。

## 备选方案

- **一开始就上 WASM 第三方插件**：安全与扩展性最好，但 v1 成本过高；后置。
- **原生动态加载**：Rust ABI 不稳定、跨平台与安全问题严重；拒绝。
- **只做数据源插件**：无法满足“v1 体现公式函数插件支持”的要求。
