# ADR-0010：本地文件数据源（CSV/JSON，手动刷新，不做监控）

- 状态：已接受
- 日期：2026-11-21
- 关联：[ADR-0008](0008-file-persistence-recovery.md) · [后端设计 §8](../architecture/backend.md#8-本地文件数据源v1)

## 背景

“从不同的数据源拿数据”是产品目标，但第一版需要控制范围与风险。用户已确认：先从本地文件开始，仅 CSV/JSON；刷新方式为手动；不监控文件变化。

## 决策

- 数据源类型：本地 CSV 与 JSON 文件；
- 读取时机：首次导入 / 用户手动刷新；**不做文件监控、不做轮询、不做后台定时读取**；
- CSV 约定：UTF-8（含 BOM）、逗号分隔、首行表头、类型推断（失败按字符串）；
- JSON 约定：顶层数组、元素为扁平对象、缺字段为空、嵌套值先按 JSON 字符串；
- 安全与资源：文件必须先由用户显式选择/授权；建议上限 32 MB / 20 万行，超限返回可读错误（流式解析后置）；
- 数据快照：解析成功即持久化 Dataset 版本（内容寻址），刷新失败保留旧版本，打开文件优先使用缓存并标注快照时间；
- 数据源在文件内是描述符（connector id + 配置），实际读取由官方连接器插件完成；
- 插件被禁用/缺失时，该数据源降级为“只读展示上次快照”，不影响文件其他部分。

## 理由

- CSV/JSON 解析无重依赖、跨平台、易于测试，适合作为插件契约的试金石；
- 手动刷新让“数据陈旧”成为明确、可解释的产品行为，同时避免后台 IO 与资源占用；
- 数据快照缓存使文件在源文件变化/丢失后仍可打开，符合崩溃恢复与本地优先目标。

## 后果

- 优点：范围可控、无需 watch 机制、无后台资源占用；数据快照与恢复模型自然衔接。
- 成本/风险：
  - 数据可能过期，UI 必须展示“上次刷新时间”并提供刷新入口；
  - 大文件解析会占用内存/CPU，需要上限与后续流式优化；
  - xlsx 等格式需要额外解析器，后置。
- 未来演进：数据库/HTTP 连接器、xlsx、流式解析、增量刷新；均复用同一 `DataSource`/`Dataset` 契约。

## 备选方案

- **xlsx 优先**：与 Excel 体验更贴近，但解析复杂且需要额外 crate；先 CSV/JSON 验证契约。
- **文件监控/自动刷新**：实时性更好，但资源占用、跨平台差异与冲突处理复杂；用户已明确不需要。
- **数据库优先**：能力更强，但依赖连接/凭据/网络，偏离本地优先与 v1 范围。
