# ADR-0006：AI 采用服务端 Provider 抽象 + 受控工具调用

- 状态：已接受（MVP 待实现）
- 日期：2026-11-21

## 背景

产品定位“AI 原生”。AI 需要读写表格、解释公式、生成计算模型。直接在前端调用模型 API 会导致：密钥泄露、跨域限制、无法访问本地数据/自定义函数、无法统一审计与限流。

## 决策

- **AI 调用统一放 Rust 后端**（未来 `crates/ai` 或 `backend/crates/server` 的 `ai` 模块）：
  - Provider 抽象：`ChatProvider` trait，首批支持 OpenAI 兼容协议（OpenAI / DeepSeek / OpenRouter 等）与 Ollama；Anthropic 适配器随后。
  - 流式：后端以 SSE 向前端推送 token 与工具调用事件（`/api/v1/ai/chat`）。
  - 密钥：只从后端环境变量 / 系统钥匙串读取，绝不进入浏览器。
- **工具调用而非直接写文件**：定义最小工具集
  - `read_range(sheet, range)`、`get_workbook_schema()`：只读上下文
  - `set_formula(sheet, range, formula)`、`write_range(...)`：写操作，需要前端确认或进入 Undo 栈
  - `explain_formula(...)`：纯计算说明
  - 工具在 Rust 侧校验范围与权限，前端执行 mutation（保持交互引擎为唯一写入口）。
- **上下文最小化**：只发送当前选区、相关表头与工作簿结构摘要，不默认发送整张表；提示用户数据将发送给哪个 provider。
- **本地优先**：默认支持 Ollama；无 key 时 AI 面板保持禁用并给出配置指引。

## 后果

- 优点：密钥安全、可审计、可限流、能访问插件与本地数据；前端无需处理各家协议差异。
- 成本：后端需要处理流式协议、工具调用循环、超时与重试；模型响应质量依赖提示工程与工具设计。
- 风险：
  - 模型误写表格：写工具默认“建议模式”（返回 diff，由用户确认应用），v0.3 再开放“自动应用”。
  - 隐私：本地 Ollama 完全离线；云端 provider 需明确提示并记录。
  - 成本：需要 token 预算与截断策略。

## 备选方案

- **前端直连模型**：实现最快，但密钥暴露、CORS、无法访问本地能力；不采用。
- **只做“生成公式”不做工具调用**：体验接近 Copilot，但无法完成“改表/解释整表”等目标；作为 MVP 第一步，再演进到工具调用。
